# 识海 · MindSea

给 [DeepSeek Harness](https://github.com/deepseek-ai) 的一个记忆插件。

它做的事很简单：**你们聊完一轮，它把这一轮的话判一遍、存进本地 SQLite**，下次要用的时候能翻出来。
不是让模型「记住」——上下文的记忆会过期，这个不会。

数据全在本机一个 `.db` 文件里，不联网、不上传。

---

## 它跟别的记忆插件有什么不一样

大多数记忆插件存的是「知识卡」：一段话压缩成一张卡，卡上写标题、摘要。

识海存的是**原话**，然后在原话上面叠三层结构：

```
话（memories）—— 一句一句，原文不动
 └ 事（events）—— 这件事叫什么，比如「记忆系统重做」
    └ 版本（versions）—— 这套方案的一版，比如「卡片墙」
       └ 阶段（stages）—— 走到哪一步，比如「试跑」
决定（decisions）—— 某个节点上定下来的口径，单独记
```

好处是：话永远不会被改写，怎么归类都可以后来再改；坏处是库会长得比较快。

每条话还会带：分数（0~100 有多重要）、七情（喜/怒/哀/惧/爱/恶/欲）、门类（闲聊/暧昧/干活/知识/规矩）、去处（进事 / 闲聊池 / 废料池）。

## 安装

**一条命令**（0.4.4 起）：

```bash
node scripts/install.mjs
```

它做三件事：

1. 把本包 link 进你的 DSH profile（`node_modules/dsh-mindsea`，Windows 用 junction）
2. 把 `dsh-mindsea` 写进 profile 的 `dsh.profile.bundles`（**改之前先备份 package.json**）
3. 库不存在就建一个空库

找不到 profile、或者有多个 profile 时它会列出来让你指定：

```bash
node scripts/install.mjs --profile "C:\Users\你\.dsh\profiles\desktop"
```

其它参数：

```bash
node scripts/install.mjs --db "D:/memory/sea2.db"   # 库放别处
node scripts/install.mjs --dry-run                   # 只看会做什么，不动手
```

**然后还要两步**（脚本会提醒你）：

1. 确认 profile 的 `cordis.patch.yml` 里有这一段：

```yaml
- id: mindsea
  name: dsh-mindsea
  config:
    dbPath: 'I:\鱼宝的记忆\sea2.db'
    autoCapture: true
```

2. 重启 DSH（或者用 `plugin_manager` 把 `include:mindsea` 关一次再开）

重启后侧边栏会多一个「识海」入口。第一次聊完一轮，库里就会有数据。

> **只想建库不想装**：`node scripts/init-db.mjs [路径]`，默认在**插件目录的上一层**建 `sea2.db`。

> 库换个位置：设环境变量 `DSH_MINDSEA_DB=<路径>`，或者在 `cordis.patch.yml` 里给这行加 `config: { dbPath: '...' }`。

## 三个工具

模型自己能调用，你也可以在对话里让它用：

| 工具 | 干什么 |
|---|---|
| `memory_search(q, day, emo)` | 撞词 / 撞日期 / 撞七情 → 命中的事，按命中条数排 |
| `memory_event(name)` | 给一个事名，摊开它的版本、阶段、最近的决定 |
| `memory_write(items)` | 把一批判好的话写进库（事 / 版本 / 阶段同名自动复用） |

三根轴可以任意组合，多个条件是「并且」：

```
memory_search(q: "桌宠", day: "2026-10")
memory_search(emo: "爱", limit: 20)
```

## 取的时候怎么取（0.4.0 起）

`memory_search` 走的是「闲聊池 + 只给词」这条路时，用新检索（`lib/search2.mjs`）：

1. **分词**：中文 2-gram + 单字 + 英文整词。单字是必须的——`老爸胃不好` 切成 2-gram 会得到「爸胃」「胃不」，关键的那个「胃」反而丢了
2. **同义词扩展**：`lib/terms.json`，17 组。`那台机器` → 出租屋笔记本、`备份那天` → 备份/演练/快照
3. **IDF 打分**：稀有词权重高。IDF 在**候选集**上算，不是全库扫
4. **长度归一 + 加权**：长条目不再靠字数堆分数；再乘 α 重要度、β 可信度、沉底惩罚

**同一批 5 个查询：子串匹配 0/5 → 关键词 + IDF 4/5。**

代价是延迟：

| 场景 | 条数 | 耗时 |
|---|---|---|
| 90 天窗口（默认） | 13.6 万 | 233~553 ms |
| 全库 | 13.6 万 | 0.9~2.1 s |

所以 `windowDays` **默认 90 天**，要看更早的得显式传（比如 `windowDays: 365`，或 0 = 不限）。

**想退回旧检索**：环境变量 `MINDSEA_SEARCH_V2=0`，不用改代码。

## 会话开头会看到什么（0.4.0 起）

两样东西注进系统提示，都只在**会话开头**算一次：

**投影** —— 一小块「定过的事」，600 字封顶

来源是 `memories.pinned = 1` 的条目（≤10 条，顺序按 id）。为什么是手工钉而不是自动挑：自动挑试过三条路都不行（`dec` 按分数排会捞出流程标题、`decisions` 表按时间排会掺早已过期的一次性决定、按分数排又让老事占坑），根子是库里没有「这条到今天是否仍有效」这个字段，只有人能判。

没钉任何东西时退回自动逻辑：`decisions` 表里 text ≤ 60 字、30 天内、同一件事只取一条。

**selfNote** —— 我自己写下的话，会话开头想起来一次

只记「我自己」那半，不记用户说过什么。不每轮注入的原因写在 `lib/selfnote.mjs` 顶部：每轮灌进去不是成长，是洗脑。

两块都是**会话内冻结**的。冻结的理由很硬：投影在系统提示里、位置在历史之前，它一变后面整个历史的缓存全部重算。

## 自动沉淀是怎么跑的

挂的是 `agent/turn-stopping`：

1. 一轮结束，抓这一轮**新增**的 user / assistant 消息；
2. 剥掉运行时注入（环境快照、system-reminder、技能目录那些不是人说的话）；
3. 丢给模型判：这条归哪件事、多少分、什么情绪、是不是决定、哪个门类；
4. 落库。

几条设计上的取舍，用之前值得知道：

- **监听器里不等模型**。`turn-stopping` 是串行事件，在监听器里 await 会把整轮收尾拖住，所以抓完增量就丢后台队列。
- **原话不由模型回抄**。模型只输出编号和判断，正文用我们自己存的原话，一个字都不会被改写。
- **短轮也存**。一轮话太短就不问模型了，直接进闲聊池、40 分、不挂事——宁可留平，不要丢。
- **我的长回答看内容**。超过 400 字、又没信息量（纯过程叙述）的，进废料池：留档，但不挂事、不参加匹配。
- **只沉淀顶层会话**。子代理（工具工人）的话不进库。

想关掉自动沉淀：在 profile 的 `cordis.patch.yml` 里给 `mindsea` 那行加

```yaml
- id: mindsea
  config:
    autoCapture: false
```

沉淀失败不会打扰你，会写进 `data/capture-log.jsonl`；面板「自动化」页能看到最近流水。

## 面板

侧边栏「识海」进去，十一页：

- **记忆库** —— 卡片墙，按门类上色，能搜、能筛
- **知识星图** —— 把事 / 版本画成星图，能拖能转
- **工作流** —— 按话题 → 事 → 版本 / 阶段看
- **时间** —— 按天看话，每条话旁边可以改门类 / 去处（判错了手动纠）
- **人设 / 遗忘 / 走神 / 日记 / 自动化 / 运行状态 / 报错**

面板的数据接口全是只读 GET，只有一个写口子：`POST /mindsea/api/memory`，用来改一条话的门类或去处。

## 目录结构

```
index.js             插件入口：三个工具、两个钩子、面板路由
client.js            面板前端（一块 Web 组件）
lib/query.mjs        只读查询（memory_search / memory_event 走这里）
lib/search2.mjs      新检索：分词 + 同义词 + IDF + 长度归一（0.4.0）
lib/terms.json       同义词 / 指代表，17 组（0.4.0）
lib/project.mjs      投影：会话开头那块「定过的事」，冻结一次（0.4.0）
lib/selfnote.mjs     selfNote：只记「我自己」的话（0.4.0）
lib/write.mjs        写入（memory_write 和自动沉淀共用）
lib/capture.mjs      自动沉淀：切轮、剥噪声、判、落库；含 scope 分级（0.4.0）
lib/routes.mjs       面板的 HTTP 路由
lib/api.mjs          面板各页要的数据
lib/tail.mjs         每个会话第一轮推最近 10 句
lib/sea-svg.mjs      现画一张识海图谱（SVG）
lib/ui/eternal.css   面板样式
scripts/init-db.mjs  建空库
test/capture-selftest.mjs  离线自测（假模型 + 库副本）
```

跑一遍自测：

```bash
npm test
```

它不碰真库、不调真模型，用一份库的副本走完整条链路。

## 已知限制

**这是最该看的一节。下面每一条都是我自己撞过的，不是「理论上可能」。**

### 能力上的

- **只在 DSH 跑着的时候沉淀**。关机、DSH 没开，那段时间的话不会进库。
- **判错要人来改**。模型会把某句判进错的事、错的分数，这个它自己发现不了；去「时间」页手动纠。
- **检索没有语义，只有词**。换一种完全不同的说法可能撞不到。具体例子：想找「备份那天」说的话，但那条记录里压根没出现「备份」这个词——同义词表也补不上，这个短板目前接受。
- **投影是手工钉的**。新发生的重要事**不会自动**进投影，得手动把 `memories.pinned` 置 1。这是刻意选的：自动挑试过三条路都不干净，宁可要可控。
- **新检索只覆盖一条路径**。`memory_search` 用 `pool=chat` 且只给 `q` 时才走 `search2`；其他组合还是旧查询。想全量走新检索需要再改 `lib/query.mjs`。

### 还没被验证的

- **沉底/复活机制没跑出数据**。「180 天没被取到就沉底、30 天内又命中就复活」逻辑写了、脚本跑了，但库才十几天，等于没验证过。真正的考验在半年后。
- **规模只测到 13.6 万条**。再往上（50 万、100 万）没测过，不知道瓶颈在哪。
- **多用户/多设备没测**。目前默认一个 DSH profile 一个库，并发写入只做了最朴素的「忙就等」。

### 工程上的

- **库只长不缩**。废料池的原文一直留着，没有自动归档（沉底只降权，不删）。
- **界面那块是从 memory-eternal 借的**（见 NOTICE），不是原创设计。
- **升级不保证向后兼容到 0.3.x**。0.4.0 加了列，新库没问题；如果从 0.3.x 升上来遇到异常，看 CHANGELOG 里对应版本的说明。

## 要花多少钱

**每轮写记忆要额外调一次模型**（判 kind / 打分 / 归类）。这笔钱没法省，除非关掉自动沉淀。

按「平均日 800 次模型调用」估（详见 `记忆调研/17-架构定稿与年推演.md`）：

| 项 | 一年 |
|---|---|
| 总花费（含日常对话） | 约 2,800 元 |
| 其中可归到记忆插件的 | 约 200~500 元 |
| 投影冻结省下的 | 约 200~2,000 元（取决于调用频率） |

**换算**：分摊到每天，记忆这套大概 **一块多**。

三个变量会显著改变这个数：模型单价、每天真聊多少轮、prefix 缓存命中率。**缓存是最要命的一个**——投影或系统提示一变，整段历史都要重算，单次成本能翻十倍。这也是投影必须冻结的原因。

> 这些数是推演，不是账单。真要记账看自己 profile 的 token 用量。

---

**0.3.x → 0.4.0：不需要迁移。** 新增的列（`scope` / `status` / `kind` / `pinned`）都按默认值处理，旧行照常可读可搜；新写入自动填。

升级动作就一步：换掉插件目录，重启 DSH。

**下个版本会不会需要迁移**，看 CHANGELOG 顶部的版本号规则——只有主版本号（1.0.0）才表示需要迁移，并且会单列升级步骤。
